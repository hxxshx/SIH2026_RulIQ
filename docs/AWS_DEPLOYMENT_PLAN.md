## 🏛️ Executive Summary

**RULIQ** is structured as a decoupled cloud-native application:
1. **Frontend:** Next.js 16 (App Router) serving the administrative dashboard, interactive NetworkX visualizer, compliance audit trail, and human-in-the-loop review interface.
2. **Backend API:** High-performance Python FastAPI service hosting deterministic graph analysis algorithms, alert rule scanners, and document evidence handlers.
3. **Persistence Layer:** PostgreSQL 16 relational database with `pgvector` for vector similarity search over statutory regulatory clauses.
4. **Storage Layer:** Object storage for institutional evidence documents (fire safety NOCs, land deeds, faculty rosters).

This document details two deployment tracks:
- **Track 1 (Recommended for Student Hackathon Prototype):** Low-cost / Free-tier optimized deployment ($0 - $15/month).
- **Track 2 (AICTE National Enterprise Production):** High-availability, Multi-AZ, auto-scaling government deployment.

## 🚀 Track 1: Step-by-Step Student Hackathon Deployment

### 1. Database Provisioning (Amazon RDS PostgreSQL 16)
1. **Engine:** PostgreSQL 16.x
2. **Instance Class:** `db.t4g.micro` (2 vCPU, 1 GB RAM — Free Tier eligible).
3. **Storage:** 20 GB General Purpose SSD (gp3).
4. **Network:** Inside Default VPC, private subnet group.
5. **Enable pgvector extension:**
   Connect via `psql` or DBeaver:
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ```
6. **Set Connection String in Secrets:**
   ```text
   postgresql+psycopg://ruliq_admin:<SECURE_PASSWORD>@<RDS_ENDPOINT>:5432/ruliq_prod
   ```

### 2. Evidence Storage Provisioning (Amazon S3)
1. **Bucket Name:** `ruliq-evidence-repository-<region>`
2. **Block Public Access:** **ON** (All 4 settings enabled).
3. **Default Encryption:** Server-Side Encryption with Amazon S3 managed keys (SSE-S3).
4. **CORS Configuration:**
   ```json
   [
     {
       "AllowedHeaders": ["*"],
       "AllowedMethods": ["GET", "PUT", "POST"],
       "AllowedOrigins": ["https://ruliq.aicte.gov.in", "https://*.amplifyapp.com"],
       "ExposeHeaders": ["ETag"]
     }
   ]
   ```
5. **Pre-signed URL Access:** Official reviewers receive time-limited (15-minute) pre-signed download URLs generated by the FastAPI backend; files are never publicly exposed.

### 3. Backend Container Deployment (AWS App Runner)
**Why AWS App Runner?** It provides fully managed container execution, automated TLS certificate provisioning, built-in load balancing, and zero-infrastructure management at a fraction of ECS cost.

1. **Build and Push Backend Image to Amazon ECR:**
   ```bash
   # 1. Authenticate Docker with Amazon ECR
   aws ecr get-login-password --region ap-south-1 | docker login --username AWS --password-stdin <AWS_ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com

   # 2. Create Repository
   aws ecr create-repository --repository-name ruliq-backend

   # 3. Tag and Push
   docker build -t ruliq-backend ./backend
   docker tag ruliq-backend:latest <AWS_ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com/ruliq-backend:latest
   docker push <AWS_ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com/ruliq-backend:latest
   ```

2. **Configure App Runner Service:**
   - **Source:** Container image from Amazon ECR.
   - **Port:** `8000`.
   - **vCPU & Memory:** 1 vCPU, 2 GB Memory.
   - **Environment Variables:**
     - `DATABASE_URL`: Stored referencing AWS Secrets Manager.
     - `BACKEND_CORS_ORIGINS`: `["https://main.<app-id>.amplifyapp.com"]`
     - `DEBUG`: `false`
     - `UPLOAD_DIR`: `/tmp/uploads` (fallback when S3 mode active)
     - `AWS_S3_BUCKET`: `ruliq-evidence-repository`

### 4. Frontend Deployment (AWS Amplify Hosting / Vercel)
1. Connect the Git repository (branch `main`).
2. Amplify automatically detects Next.js SSR build specifications.
3. Configure Environment Variables:
   - `NEXT_PUBLIC_API_URL`: `https://<apprunner-id>.ap-south-1.awsapprunner.com/api/v1`
4. Deploy: Build completes in ~2 minutes with global edge caching and free SSL.

```text
                 ├── WORM (Write Once, Read Many) compliance mode for evidence
                 └── KMS customer-managed encryption key (SSE-KMS)
```

## 🔒 Security & Statutory Compliance Checklist

1. **Least-Privilege IAM Roles:**
   - App Runner tasks assume a dedicated IAM execution role granting ONLY `s3:GetObject` and `s3:PutObject` on the specific evidence bucket prefix.
2. **Zero Hardcoded Credentials:**
   - Database credentials, API tokens, and JWT secret keys reside strictly in **AWS Secrets Manager**.
3. **Encrypted Transit and Rest:**
   - All communications enforce TLS 1.3 in transit.
   - RDS storage, S3 buckets, and EBS snapshots are encrypted at rest with AES-256.
4. **Tamper-Evident Audit Trail:**
   - Audit logs recorded in PostgreSQL ledger table with append-only permissions for runtime roles.
   - Optional AWS CloudTrail Lake integration for infrastructure-level operational audit records.
